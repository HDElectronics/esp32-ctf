# File map

- `CLAUDE.md` — agent rules and commands
- `docs/SPEC.md` — goals, architecture, flag scheme, full challenge catalogue
- `docs/PLAN.md` — ordered tasks and status
- `CMakeLists.txt` — top-level ESP-IDF project (esp32_ctf)
- `sdkconfig.defaults` — target/flash/partition/console/Bluedroid dual-mode/coex defaults; Wi-Fi IRAM opts off (IRAM headroom)
- `partitions.csv` — 4 MB layout: nvs, phy_init, factory 2560K, notes, storage (SPIFFS)
- `dependencies.lock` — managed component lock (espressif/mdns)
- `main/` — boot sequence
- `main/main.c` — app_main: platform init, SER-01 boot banner, always-on + mode tracks, console start; optional size-probe stubs
- `main/Kconfig.projbuild` — `CONFIG_CTF_SIZE_PROBE` (dev only, default n)
- `main/idf_component.yml` — managed deps (espressif/mdns)
- `components/ctf_core/` — portable flag/registry/scoring engine (no IDF headers, no heap)
- `components/ctf_core/include/ctf_core.h` — public API: catalogue, flags, derive, submit, answer gates, points wallet, hint tiers (price/tier/buy), backend
- `components/ctf_core/include/ctf_sha256.h` — SHA-256 / HMAC-SHA256 API (usable by tracks, e.g. JWT)
- `components/ctf_core/ctf_core.c` — engine state, XOR-split key, derivation, submission, wallet + hint tiers, tagged progress record v2
- `components/ctf_core/ctf_catalog.c` — static 40-challenge catalogue (SPEC order = progress bit index) + 3 hint tiers each
- `components/ctf_core/ctf_sha256.c` — portable SHA-256 + HMAC-SHA256 implementation
- `components/ctf_platform/` — IDF glue: NVS, MAC, mode, console
- `components/ctf_platform/include/ctf_platform.h` — public API: `CTF_FW_VERSION`, init, MAC, board name, mode get/set+reboot, console byte hook, console start
- `components/ctf_platform/ctf_platform.c` — NVS init + ctf_core backend (ctf/progress), mutex, MAC, mode (ctf/mode), esp_console init
- `components/ctf_platform/ctf_console.c` — UART0 line editor task (raw-byte hook, echo, backspace, `ctf> ` prompt) → esp_console_run; SOH lines → ctf_api_run
- `components/ctf_platform/ctf_commands.c` — core commands: status, list, submit, answer, hint (tiers), mode, reset
- `components/ctf_platform/ctf_api.c` — machine channel `api info|list|submit|hint|answer|mode`: JSON writer, one STX/ETX frame per line in a single write
- `components/ctf_platform/ctf_platform_priv.h` — internal: ctf_commands_register, ctf_platform_save_mode, ctf_api_run
- `components/track_*/` — one component per challenge track; `track_<name>_start()` called from app_main
- `test/host/` — host build + unit tests for ctf_core
- `test/host/CMakeLists.txt` — builds components/ctf_core/*.c + test_*.c, registers with ctest
- `test/host/test_util.h` — CHECK/RUN macros, in-memory backend, test group declarations
- `test/host/test_main.c` — runner `main`, in-memory backend with lock-nesting tracking, test MACs
- `test/host/test_crypto.c` — SHA-256 vectors, RFC 4231 HMAC cases 1-4, 6, 7
- `test/host/test_catalog.c` — catalogue vs SPEC (IDs, names, levels, kit, 3 hint tiers), values, max score, hint prices
- `test/host/test_flags.c` — flag format/determinism/MAC sensitivity, derive, submit normalisation, answer gates
- `test/host/test_progress.c` — wallet + tier buying, record v2 layout/persistence, v1/orphan-tier3 handling, tampered record, reset, no backend
- `test/host/check_hints.py` — lints the 3 hint tiers in `ctf_catalog.c`: 40 entries, non-empty, ASCII-only, per-tier length limits, no flag/placeholder, distinct tiers
- `components/track_serial/` — SER-02..04 (UART2 beacon, timing login, escape hook) + CRY-01 shard 1
- `components/track_crypto/` — CRY-01..03 console commands (`cipher`, `oracle`, `msgs`); Kconfig `CONFIG_CTF_CRYPTO_DEV`
- `solvers/serial/` — SER solvers + `_util.py` console helpers (pyserial)
- `solvers/crypto/` — CRY solvers
- `components/track_re/` — RE-01..04 boot-time provisioning (notes partition, NVS vault k/chk, SPIFFS blob.bin) + `unlock` command; mounts SPIFFS
- `solvers/re/` — RE solvers (esptool dump + nvs_tool.py), `_util.py`, README with Ghidra loading guide
- `components/track_hw/` — HW-01..06 (jumper check, Morse LED, LEDC PWM, bit-banged I2C/SPI, touch keypad), `keypad` cmd; Kconfig `CONFIG_CTF_HW_DEV` (`hwdev` cmd)
- `solvers/hw/` — HW solvers/decoders, `_util.py`, README with manual kit steps
- `components/track_ble/` — BT bring-up (BTDM + Bluedroid), advertising/BLE-07 rotation, GATT challenge + CTF control services, BLE-01..11, CRY-01 shard 2, `ble` cmd; `track_ble_bt_ready()`
- `solvers/ble/` — bleak solvers ble01..ble11, `_util.py`, README.md (GATT table, UUIDs)
- `components/track_btc/` — BTC-01..03: SPP console + shell, BR/EDR name/CoD/EIR, CRY-01 shard 3
- `solvers/btc/` — BTC solvers (D-Bus inquiry, SDP/RFCOMM), `_util.py`, README (BTC-03 encoding; needs /usr/bin/python3 for AF_BLUETOOTH)
- `components/track_web/` — WEB-01..09, /score, /submit, CRY-01 shard 4, `wifi` cmd; Kconfig `CONFIG_CTF_WEB_DEV_STA*` (dev LAN testing)
- `components/track_web/web_http.c` — port-80 handlers, JWT, /diag confinement, WS, /score, /submit
- `components/track_web/web_net.c` — WEB-08 mDNS beacon, WEB-09 knock/door
- `components/track_web/www/` — embedded page templates + robots.txt
- `solvers/web/` — web solvers (`--host`), `_util.py` (DTR/RTS-safe serial open), README
- `sdkconfig.dev.local` — (git-ignored, user-created) dev STA Wi-Fi credentials overlay
- `solvers/common/console.py` — shared no-reset board serial Console (all tracks; `--port` / `$CTF_PORT`)
- `solvers/common/api_check.py` — machine-channel protocol check (frames, no echo, wallet, hint tiers, `status`/`hint` output, `api mode` reboot; `--fresh` wipes progress)
- `solvers/README.md` — solver setup: venv from /usr/bin/python3, port option, organizer-only (spoilers)
- `README.md` — short visual overview: banner, quick start, tracks, modes, hardware, toolbox pointers, organizer links
- `docs/toolbox.md` — full per-track tool table + install hints (moved from README)
- `docs/development.md` — build from source, release script, host tests, dev options (Wi-Fi password warning), organizer notes
- `docs/img/` — README images, `<name>-light.png` / `<name>-dark.png` at 2x (`console.png` and `app.png` single, always dark)
- `docs/img/src/` — one self-contained HTML source per image (`?theme=dark` for dark); `make_i2c.py` generates `i2c.html` from a sigrok capture (`.sr` not in repo); `app-seed.html` seeds the player app's progress for `app.png`
- `scripts/render-images.sh` — renders `docs/img/src/*.html` to `docs/img/*.png` with headless Chrome; `app` serves the repo on :8012 and shoots the real player app
- `docs/players/` — spoiler-free player guides: index + one per track
- `scripts/release.sh` — app-content `--check` guard, clean release build, dev-option guard, merged .bin → dist/, ESP Web Tools manifest, web/flasher/dist-site/ (flasher at root + player app in app/, cross-links rewritten)
- `web/flasher/` — flasher landing page (esp-web-tools 10.4.0) + manifest; hero links to the player app
- `web/app/` — player app (static, no build): offline guide and scoreboard, never opens the board's port; README for local serving
- `web/app/index.html`, `web/app/app.css` — Setup (MAC entry) + Play screens per `docs/design/player-app/`, design tokens
- `web/app/js/main.js` — app state, rendering, hints/flag/answer actions, Progress menu (export/import/reset), primer view, deep-link params
- `web/app/js/engine.js` — WebCrypto HMAC flag bodies / derived values (same as ctf_core), flag normalisation, MAC parsing, HW-03 answer check
- `web/app/js/store.js` — points wallet + hint tiers per board MAC in localStorage (memory fallback), export/import validation
- `web/app/js/markdown.js` — tiny escaping Markdown renderer for primers
- `web/app/content/board-data.json` — generated from firmware sources: flag key, catalogue, hint texts + prices, start points, answer gates (do not edit)
- `web/app/content/challenges.json` — generated briefs + tools per challenge (do not edit; see build-app-content.py)
- `web/app/content/primers/<track>.md` — per-track primers (ble, btc, web, serial, hw, re, crypto)
- `scripts/build-app-content.py` — ctf_core.c/.h + ctf_catalog.c + track_hw.c → board-data.json; docs/players/*.md → challenges.json (`--check` for staleness)
- `LICENSE` — MIT
- `docs/design/player-app/` — approved player-app mockups (Design Component HTML), v0.2.0 reference
- `web/app/content/primers/` — spoiler-free 3-minute track primers (`<track>.md`) rendered in the player app, + README with style rules
- `web/app/tests/engine.test.mjs` — Node test: engine vs node:crypto HMAC, flag/MAC parsing, HW-03 gate; real boards from the ignored `.cache/real-boards.local.json` (skipped when absent)
- `web/app/tests/store.test.mjs` — Node test: wallet (prices, tier order, points), per-MAC storage, memory fallback, export/import over a fake localStorage
- `hardware/defuse32/` — Defuse32 rev 0 hardware: carry case with six module plates + carrier PCB (no firmware yet)
- `hardware/defuse32/README.md` — front door: renders, BOM summary, regenerate commands, what to fabricate, what to measure, status
- `hardware/defuse32/SPEC.md` — authoritative hardware spec: case/panel/plate grid, carrier parts, ESP32 + MCP23017 pin maps, connectors, plate modules
- `hardware/defuse32/docs/parts.md` — Defuse32 case choice (Pelican 1520 + 1520PF), panel support, depth budget, per-module dimensions with sources (verified/typical)
- `hardware/defuse32/data/parts.json` — same numbers in mm for the FreeCAD and KiCad generators (case, panel frame, panel holes, modules; convention at top)
- `hardware/defuse32/kicad/` — KiCad 10 carrier project, **rev 2** (SMD, 100 × 70 mm): root sheet + `power_usb/esp32/io/connectors.kicad_sch`, `defuse32-carrier.kicad_pcb` (routed), `.kicad_dru` (JLCPCB rules), local libs `defuse32.kicad_sym` (CH340C_3V3) + `defuse32.pretty/` (ESP32-WROOM-32E_JLC, edge-mount USB-C), README; rev 1b is git tag `carrier-rev1b`
- `hardware/defuse32/kicad/gen/` — generators: `design.py` is the source of truth (parts, pin→net map, placement); `gen_lib.py`, `gen_sch.py`, `gen_pcb.py` write libs/schematic/board; `check_netlist.py` checks netlist + PCB pads against `design.py`; `sexp.py`, `symlib.py` helpers
- `hardware/defuse32/kicad/out/` — generated: schematic PDF, `bom.csv`, netlist, `erc.rpt`, `drc.rpt`, `audit.json` (finish audit)
- `hardware/defuse32/cad/build.py` — FreeCAD entry point (`freecad.cmd`): case, frame, panel, plates, carrier, fit checks, exports, `renders/cad_*.png`
- `hardware/defuse32/cad/d32lib.py` — FreeCAD helpers: primitives, cut/engrave records, module placeholder builders, DXF/GLB/STL writers
- `hardware/defuse32/cad/layout.py` — plate grid and per-plate module layout (plate-local coords), assumed extra parts, proposal values
- `hardware/defuse32/cad/README.md` — CAD regenerate options, outputs, coordinates, plate cut-out tables, last fit checks, values to measure
- `hardware/defuse32/cad/defuse32.FCStd`, `hardware/defuse32/cad/out/` — generated: assembly FCStd; panel/plate DXF + STL, assembly STEP/GLB, `fit_report.txt`, `plate_cutouts.md`
- `hardware/defuse32/cad/carrier.step` — generated by KiCad (`kicad-cli pcb export step`), imported by `build.py`
- `hardware/defuse32/renders/` — PNGs: `carrier-*.png` from KiCad (3D renders `carrier-top/iso`, 2D layer plots `carrier-f-cu/b-cu/silk`), `cad_*.png` from FreeCAD (each side writes only its own)
- `hardware/defuse32/kicad/gen/route_prep.py` — rev 2 Freerouting round trip (prep, SES import, finish: GND stitching + `HAND_FIXES`); `gen_jlcpcb.py` writes `out/jlcpcb/`; `gen_pcb.py` refuses to overwrite the routed board without `--force`
- `hardware/defuse32/kicad/gen/polish.py` — rev 2.1 finish of the routed board: jog straightening (moves, pushes, local octilinear re-route), GND pours 0.2 mm + island/grid stitching, narrow-strip closing, silkscreen (references, callouts, legend, plate names), DRC, report; `gen/pcb_audit.py` is the pcb-layout-pro finish audit (copy)
- `hardware/defuse32/kicad/out/jlcpcb/` — JLCPCB Gerbers/drill zip, assembly BOM + CPL (LCSC numbers), order-settings README; `out/defuse32-carrier.ses` is the Freerouting session the board was built from
- `hardware/defuse32/FIRMWARE.md` — firmware spec: game rules, packs, console, v0 module challenges
- `hardware/defuse32/firmware/` — Defuse32 ESP-IDF project (esp32): CMakeLists (COMPONENTS main, ctf_core extra dir), sdkconfig.defaults, dependencies.lock, README
- `hardware/defuse32/firmware/main/` — app_main (board init, banner, SD mount, boot pack), `game.c` (10 ms game task, UI, key switch, tilt), `console_cmds.c` (hw/round/pack commands), `Kconfig.projbuild`
- `hardware/defuse32/firmware/components/d32_engine/` — portable game engine (C11, host-testable, no IDF headers)
- `hardware/defuse32/firmware/components/d32_board/` — `board.h` pin map + presence table; drivers (I2C, MCP23017, keypad/wires/encoder, TM1637, OLED, WS2812, buzzer/servo, touch, IR, LDR, LIS3DH (`board_lis3dh.c`) + portable tilt math (`board_tilt.c`, host-tested), SD, UART2, PN532 stub)
- `hardware/defuse32/firmware/components/d32_pack/` — pack JSON parser (portable) + SD loader
- `hardware/defuse32/firmware/components/d32_modules/` — module adapters `mod_*.c`, registry, buzzer arbiter, `d32_mod_logic.c` (portable)
- `hardware/defuse32/firmware/test/host/` — host tests (engine, pack parser, module logic): `cmake -S hardware/defuse32/firmware/test/host -B build-d32-host`
